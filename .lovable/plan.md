# 일간 플랜: 늘리기 UI 단순화 + 필기 끊김 버그 수정

## 1. 늘리기만 남기고 줄이기 삭제

- "세로 줄이기", "가로 줄이기" 버튼과 관련 로직을 제거합니다. 한 번 늘린 영역은 그대로 유지됩니다.
- 하단의 "가로 n × 세로 n" 텍스트 표시도 제거합니다.

## 2. 화살표 버튼만, 스크롤 영역 가장자리 중앙에 배치

- 텍스트 라벨 없이 화살표 아이콘 버튼만 둡니다.
  - 아래로 늘리기: 필기 영역 **하단 가장자리 중앙**에 아래 방향 화살표
  - 오른쪽으로 늘리기: 필기 영역 **오른쪽 가장자리 중앙**에 오른쪽 방향 화살표
- 두 버튼은 스크롤 컨테이너 위에 떠 있는(sticky/absolute) 반투명 원형 버튼으로, 스크롤해도 항상 같은 자리에 보입니다.
- 접근성용 `aria-label`("아래로 늘리기" / "오른쪽으로 늘리기")은 유지하고, 최대 배수(5)에 도달하면 버튼을 숨깁니다.

## 3. 필기가 몇 번 후 점만 찍히는 문제 — 검증 후 수정

증상은 "펜을 눌렀을 때 시작점 점은 찍히지만 이후 선이 이어지지 않는다"이므로, 눌림(pointerdown)은 처리되고 이동(pointermove) 입력이 캔버스에 반영되지 않는 상태입니다. 먼저 브라우저 자동화로 반복 필기를 재현해 어느 단계에서 끊기는지(이벤트 미수신 / 포인터 캡처 실패 / 다시 그리기 실패) 확인한 뒤, 확인된 원인에 맞춰 아래 항목 중 필요한 것을 고칩니다. 현재 코드에서 이 증상을 만들 수 있는 후보는 다음과 같습니다.

- `onPointerLeave`가 `onPointerUp`에 연결되어 있어, 포인터 캡처 전환·스크롤·툴바 재렌더 시 발생하는 leave 이벤트가 그리는 도중 획을 강제 종료시킬 수 있습니다.
- 이동 처리에서 `e.buttons === 0`이면 무시하는데, 일부 스타일러스/WebView는 이동 중 `buttons`를 0으로 보고합니다.
- `setPointerCapture`가 실패(이전 포인터가 정리되지 않은 상태)하면 예외로 이후 로직이 중단되고, 캡처가 없으면 이동 이벤트가 캔버스 밖으로 새어나갑니다. 종료 시 `releasePointerCapture`를 호출하지 않는 점도 누적 원인이 될 수 있습니다.
- 저장 상태 변경(저장 중/저장됨)으로 컴포넌트가 재렌더될 때 `ResizeObserver` 재등록 → `resize()` → 캔버스 크기 재설정이 그리는 도중 발생하면 진행 중인 획이 초기화될 수 있습니다.

### 수정 방향

- 진행 중인 포인터 ID를 ref에 저장하고, 그 ID의 이벤트만 처리합니다. `pointerleave` 핸들러는 제거하고 `pointerup`/`pointercancel`로만 종료합니다.
- `buttons` 대신 "진행 중 포인터가 있는가"로 판단합니다.
- `setPointerCapture`는 try/catch로 감싸고, 종료 시 `releasePointerCapture`로 정리합니다.
- 캔버스 크기 재설정은 실제 크기(폭/높이/DPR)가 바뀐 경우에만 수행하고, 그리는 중에는 건너뜁니다.
- 획이 쌓일수록 매 이동마다 전체를 다시 그리는 비용이 커지므로, 저장된 획은 오프스크린 캔버스에 캐시하고 진행 중인 획만 위에 그리도록 바꿉니다(느려짐으로 인한 "선이 안 그려지는 것처럼 보임" 방지).

### 검증

- Playwright로 캔버스에 10회 이상 연속으로 획을 그리고, 각 획 이후 저장된 stroke 수와 실제 픽셀 변화를 확인합니다. 늘리기 후·스크롤 후에도 동일하게 확인합니다.
