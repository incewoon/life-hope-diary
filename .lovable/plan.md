# 회의록 — 제미나이 요약 버튼 로직 보완

## 지금 왜 안 되는지

현재 `MeetingRecorder`는 **공유 시트 한 가지 경로**만 씁니다. 버튼이 뜨는 조건이 `navigator.canShare({ files })` 이고, 이게 false면 "녹음 파일 저장" 버튼으로 바뀝니다. 크롬(안드로이드)에서 조건이 통과해도 공유 시트에 제미나이가 목록에 나오려면 제미나이가 그 파일 형식(webm 오디오)을 받아주어야 하는데, 제미나이 앱은 오디오/webm 공유를 받지 않는 경우가 많아 **아이콘 자체가 안 보이거나 텍스트만 전달**됩니다. 그래서 "프롬프트 자동 입력 + 파일 첨부"가 한 번에 되지 않습니다.

또 하나: 공유 시트로 넘길 때 넘긴 `text`는 앱마다 무시되거나 파일과 함께 전달되지 않습니다.

## 바꿀 방향 (프롬프트 자동 입력 우선)

audiochef의 방식과 동일하게 **제미나이를 프롬프트가 채워진 상태로 여는 것**을 기본 동작으로 삼고, 파일은 미리 저장해 두어 사용자가 첨부만 누르면 되게 합니다.

버튼 구성(녹음이 있을 때):

1. **`제미나이로 요약`** (주 버튼)
   - 프롬프트를 클립보드에 복사
   - 녹음 파일을 기기에 자동 저장(다운로드)
   - `https://gemini.google.com/app?q=<프롬프트>` 로 이동 → 안드로이드 크롬에서는 설치된 제미나이 앱이 열리고 프롬프트가 입력됨(앱이 없으면 웹 제미나이)
   - 토스트: "제미나이가 열립니다. 클립 아이콘으로 방금 저장된 녹음 파일을 첨부하세요."
2. **`공유`** (보조 버튼, `navigator.canShare({files})`가 true일 때만)
   - 기존 공유 시트 경로 유지 — 제미나이가 목록에 뜨는 기기에서는 이쪽이 한 번에 됩니다.
3. **`파일 저장`** (보조, 항상 표시)

## 그 밖의 보완

- **녹음 형식**: `MediaRecorder.isTypeSupported`로 `audio/mp4`(m4a) → `audio/webm` 순으로 선택. m4a가 제미나이·다른 앱 호환성이 훨씬 좋습니다.
- **프롬프트 길이**: URL 파라미터가 너무 길면 잘리므로 `q`에 넣는 문구는 핵심 요약 지시 + 회의명/일시/장소/참석자로 압축(약 1,500자 상한). 전체 문구는 클립보드에 그대로 복사.
- **프롬프트 문구 수정**: "첨부한 녹음 파일" → "지금 첨부할 회의 녹음 파일" 로 바꿔, 파일을 나중에 붙이는 흐름과 맞춥니다.
- **미리보기(iframe) 안내**: 미리보기에서는 공유·다운로드가 막힐 수 있으므로, 파일 저장 실패 시 안내 토스트를 띄웁니다.
- **문구 정리**: 하단 안내문은 "녹음은 화면을 벗어나면 사라집니다. 요약 전에 먼저 저장·공유하세요."로 유지.

## 기술 메모

- 변경 파일: `src/components/MeetingRecorder.tsx` 하나. `src/routes/meetings.tsx` 는 그대로.
- 이동은 `window.open(url, "_blank", "noopener")` 대신 사용자 제스처 내 동기 호출을 유지하되, 클립보드/다운로드는 먼저 처리하고 마지막에 열기.
- DB 스키마·필기 영역·일시/장소/참석자 UI 변경 없음.
