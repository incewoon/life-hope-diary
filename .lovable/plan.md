# 제미나이 요약 — 파일 저장 먼저, 제미나이는 그다음

## 지금 문제

`openGemini`가 `window.open(제미나이)`를 **먼저** 호출하고 그 뒤에 파일 저장을 실행합니다. 그래서 제미나이 앱/탭이 앞으로 나오면서 다이어리 앱의 "다운로드 저장 승인" 팝업이 뒤에 가려지고, 승인하지 않으면 파일이 저장되지 않은 상태로 제미나이만 열립니다.

## 바꿀 순서

버튼을 2단계로 나눕니다.

1단계 — **`녹음 파일 저장`** (제미나이 버튼을 누르면 먼저 이 동작 실행)
- 프롬프트를 클립보드에 복사
- 다운로드 실행 → 기기의 저장 승인 팝업이 **가려지지 않은 상태로** 표시됨
- 토스트: "저장을 승인한 뒤 아래 ‘제미나이 열기’를 누르세요."

2단계 — **`제미나이 열기`** (1단계 완료 후에만 표시)
- 이 버튼을 누를 때 비로소 `https://gemini.google.com/app?q=<프롬프트>` 로 이동
- 사용자 클릭 제스처 안에서 열기 때문에 팝업 차단도 피할 수 있음
- 토스트: "클립(+) 아이콘으로 방금 저장한 녹음 파일을 첨부하세요."

즉 자동으로 연달아 열지 않고, 저장 승인이 끝난 시점을 사용자 클릭으로 확인받습니다. 다시 녹음하면 다시 1단계로 돌아갑니다.

## 참고 (기술 제약)

브라우저는 저장된 파일의 실제 경로를 알려주지 않고, 다른 앱에 파일 경로를 URL로 넘길 수도 없습니다. 그래서 "저장된 파일 경로를 제미나이에 함께 전달"은 웹에서는 불가능하며, 제미나이에서 클립(+) → 최근 파일로 첨부하는 흐름이 현실적인 최선입니다. 파일까지 한 번에 넘기려면 기기 공유 시트가 제미나이를 받아주는 경우에만 가능해서, 기존 `공유` 버튼은 보조로 그대로 둡니다.

## 기술 메모

- 변경 파일: `src/components/MeetingRecorder.tsx` 만.
- `saved: boolean` 상태 추가. 녹음 종료(`recorder.onstop`)·새 녹음 시작 시 `false` 로 리셋.
- `openGemini` 를 두 함수로 분리:
  - `prepareForGemini()`: `copyPrompt()` → `saveFile()` → 성공 시 `setSaved(true)` + 안내 토스트, 실패 시 기존 실패 토스트.
  - `launchGemini()`: 클릭 핸들러 안에서 동기적으로 `window.open(geminiUrl, "_blank", "noopener")`; 차단 시 기존 팝업 차단 안내 토스트.
- UI: `saved === false` → `제미나이로 요약(1/2) 파일 저장`, `saved === true` → `제미나이 열기(2/2)` 주 버튼. `공유`·`파일 저장` 보조 버튼과 하단 안내문은 새 순서에 맞게 문구만 조정.
